# VGsim Predict

`VGsim Predict` - небольшой Python-интерфейс поверх VGsim для подбора интенсивностей миграции между двумя популяциями. Проект создаёт тестовое наблюдение через VGsim, считает по нему сводные признаки и траектории, а затем подбирает параметры миграции с помощью приближённого поиска по сетке.

## Что такое VGsim

VGsim - быстрый симулятор вирусных генеалогий для сценариев эпидемии в нескольких популяциях. В нашем проекте VGsim используется как генератор синтетического наблюдения: мы задаём параметры эпидемии и миграции, запускаем симуляцию, выгружаем события цепочки заражений и превращаем их в таблицу признаков.

Важная идея миграции в VGsim: миграция задаётся вероятностью нахождения индивида из одной популяции в другой. Поэтому параметры `mu_AB` и `mu_BA` в нашем интерфейсе интерпретируются как вероятности миграционного контакта из A в B и из B в A.

## Основные параметры VGsim в интерфейсе

- `sites` - число изменяемых сайтов генома.
- `pop A size`, `pop B size` - размеры двух популяций.
- `beta` - интенсивность передачи инфекции.
- `gamma` - интенсивность восстановления или удаления активного заражённого.
- `sampling` - интенсивность сэмплирования.
- `iterations` - максимальное число событий симуляции.
- `sample size` - целевой размер выборки.
- `method` - метод симуляции VGsim, например `direct`.
- `obs mu_AB`, `obs mu_BA` - истинные параметры миграции, на которых создаётся тестовое наблюдение.
- `obs seed` - seed для воспроизводимости наблюдения.

## Что считает приложение

После запуска симуляции приложение строит summary-набор признаков:

- финальное число активных заражённых в A и B;
- пики активных заражённых и моменты пиков;
- первое появление активного заражения в B;
- площади под траекториями активных заражений;
- средние значения active по популяциям;
- накопленные заражения и восстановления;
- длительность симуляции `t_end`;
- число миграционных событий `mig_AB`, `mig_BA`, их сумму и дисбаланс;
- значения траекторий на фиксированной временной сетке.

## Distance

Для сравнения кандидата с наблюдением используется составная метрика расстояния. Она объединяет:

- `trajectory_distance` - расхождение траекторий active/infect/recover;
- `aggregate_distance` - расхождение агрегированных признаков;
- `time_distance` - расхождение по длительности симуляции;
- `time_extra_distance` - штраф за выход времени за допустимую толерантность;
- `migration_distance` - расхождение миграционных диагностик.

Итоговая distance - взвешенное среднеквадратичное объединение этих частей. Веса задаются в блоке `Параметры distance`.

## Equal fit

`equal-fit` ищет один общий параметр:

```text
mu_AB = mu_BA = mu
```

Алгоритм берёт сетку `min mu ... max mu`, запускает VGsim на каждом кандидате, усредняет результат по нескольким seed, считает distance и затем несколько раз уточняет сетку вокруг лучших значений.

## Unequal fit

`unequal-fit` ищет два разных параметра:

```text
mu_AB != mu_BA
```

Алгоритм строит двумерную сетку пар `(mu_AB, mu_BA)`, прогоняет симуляции для каждой пары, выбирает лучшие пары по distance и уточняет поиск вокруг них. Это тяжелее, чем equal-fit: если `steps = 10`, то первый проход даёт уже `10 * 10 = 100` пар кандидатов.

## Шум наблюдения

Интерфейс умеет включать неполную регистрацию случаев. Параметр `reporting rate p` задаёт среднюю долю зарегистрированных значений, а `rate jitter` добавляет случайное колебание этой доли по временным точкам. Это нужно, чтобы сравнивать подбор по чистому и зашумлённому наблюдению.

## Интерфейс

Основной файл приложения - `app.py`. В нём есть блоки:

- `Сетка поиска mu` - диапазон и число точек сетки;
- `Параметры вируса и VGsim` - параметры симулятора;
- `Параметры создания тестового наблюдения VGsim` - истинные `mu_AB`, `mu_BA` и seed;
- `Модель наблюдения` - включение или выключение underreporting;
- `Параметры distance` - веса компонент расстояния;
- `Параметры refined fit` - настройки уточняющего поиска;
- `ABC posterior` - отдельный блок для грубой апостериорной картины по equal `mu`;
- `Действия` - кнопки запуска симуляции, equal-fit, unequal-fit и графиков.

## Что мы делаем в проекте

Цель проекта - научиться восстанавливать параметры миграции между двумя популяциями по данным, сгенерированным VGsim. Пока данные синтетические: мы сами задаём истинные `mu_AB` и `mu_BA`, генерируем наблюдение, а потом проверяем, сможет ли наш алгоритм найти близкие значения.

Текущая логика:

1. Запускаем VGsim с известными параметрами.
2. Из событий симуляции собираем траектории и summary-признаки.
3. При необходимости применяем шум неполной регистрации.
4. Запускаем equal-fit или unequal-fit.
5. Сравниваем кандидатов с наблюдением через distance.
6. Смотрим таблицу лучших кандидатов и график лучшей найденной симуляции.

## Запуск

```bash
python app.py
```

Перед запуском должен быть установлен VGsim и зависимости проекта.
